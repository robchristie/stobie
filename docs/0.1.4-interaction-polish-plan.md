## Outcome

Close four reusable-interaction seams before beginning usage-led analytical
work, without adding application capability or expanding the framework
abstractly:

- consume virtual-grid wheel input only when the grid can move, preserving
  parent propagation at short-content and directional boundaries;
- use one pure core calculation for virtual-grid row and item ranges;
- suppress no-op camera-drag commands and explicitly cancel retained previews
  after focus or terminal pointer loss;
- drive physical browser and native smoke tests from current Rust-owned UI
  geometry instead of fixed layout coordinates.

## Calibration and selected design

Question: can the existing presenter retain its proven 100,000-item behaviour
while matching pinned egui 0.36.1 wheel propagation and exposing enough
presentation geometry to make physical tests layout-resilient?

Smallest probes and evidence owners:

- core range tests compare partial rows, empty grids and clipped overscan;
- egui tests exercise movable, short, top, bottom and horizontal-wheel cases;
- camera tests cover an out-and-back drag, history defence and focus/pointer
  cancellation;
- Rust-owned snapshots expose finite current-frame rectangles, while Playwright
  and xdotool prove those rectangles reach the same semantic postconditions as
  the earlier fixed-coordinate paths.

The presenter keeps a narrow movement-aware compatibility shim because a
headless egui probe showed that removing it did not advance retained scroll
state on the current integration. The shim mirrors egui's movement checks and
`always_scroll_the_only_direction` behaviour, clearing input only after a real
offset change. `polyorama_core::layout_virtual_grid` is the sole authority for
row clamping, overscan and row-to-item mapping; egui supplies its exact visible
row range.

Abnormal camera termination cancels rather than commits. Normal release still
samples the final pointer first. Focus loss always cancels; `PointerGone`
cancels only when the primary button is no longer held.

UI geometry is current-frame observation data in the application test snapshot,
not document, session or workspace state. It uses egui logical points and is
mapped through the live canvas or X window by each physical harness.

## Non-goals

- no new widget, renderer, analytical operation or docking capability;
- no retained UI tree or second workspace representation;
- no change to the event-driven repaint contract;
- no claim that test geometry is durable application state or a public layout
  API.

## Verification and exit condition

Focused native/Wasm tests and architecture checks run after each increment.
The package exits only when `cargo xtask verify` passes both physical targets,
the WebGPU canvas is inspected through Lantern, evidence/report claims match the
new captures, and an independent reviewer passes the exact committed head.
