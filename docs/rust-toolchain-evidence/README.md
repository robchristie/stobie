## Discriminators and necessary repair

The original mixed browser journey failed strict admission at an edge region.
Old 1.97.1 browser/new service and old 1.97.1 browser/old 1.97.1 service reproduce
it (`delivery/old-browser-new-service/` and `delivery/old-browser-old-service/`).
The first grey and RGB fixture payloads, manifests and descriptors generated by
the old/new tool are byte-identical; only preparation timing/RSS differs
(`delivery/fixtures/old-generator/comparison.json`). This establishes the
pre-existing request mismatch rather than attributing it to the new compiler.

The codec's reduced half-open window uses ceiling start/end projection, while
the adapter previously rounded its request start down. At a tile edge this asks
the service for an extra tile-header bin outside the original authenticated
decode plan. The repair projects the request start with `div_ceil`, matching
the original demand. The regression uses the emitted request and server
`effective_region`, then compares decoded pixels/masks against a client populated
from the original codec demand. It covers aligned/interior/tile-edge/image-edge
windows and retained empty-output rejection. The old floor expression fails;
the repaired expression passes (`delivery/query-regression-before.log` and
`delivery/query-regression-after.log`). No admission, cancellation, budget, codec
revision or dependency guard is widened. A data favicon avoids Chromium's
incidental `/favicon.ico` request to the service's closed route set; the service
route policy is unchanged (`delivery/cdp-network-trace/`).

The first repaired nine-input constrained run completed without errors and
proved cancellation/representation eviction but correctly failed GPU eviction: its
9,170,944-byte peak does not reach the 16 MiB limit. The complete negative
observation is retained under `delivery/repaired-viewer-browser/`. An attempted
argument-order adjustment stopped at the catalogue identity guard before browser
execution: the service's `BTreeMap` sorts targets (`delivery/pressure-viewer-browser/`).
The final [six-input cohort](pressure-subset-cohort.json) uses original indices
`0,1,3,5,7,8`, naturally sorted, placing existing RGB images at pressure-visited
indices 1–4 while retaining both grey inputs. Every representation keeps its
original bytes, profile and immutable identity; no fixture is regenerated.
The unchanged harness has no nine-image count requirement. This successful
six-input pressure coverage is separate from the nine-input native journey and
the nine-input ordinary browser trace; it makes no representative nine-image
browser system claim. Historical probe filenames beginning `accepted-` are
provisional experiment labels, not acceptance declarations.

Initial headless SwiftShader startup failed on this host, while the same
production bytes passed the existing headful route used by normal CI. Both
observations remain (`delivery/canonical.*`, `delivery/canonical-before-adapter-repair.*`).
Final repaired full canonical evidence uses the maintained headful contract.
No host libraries or machine/default toolchains were changed.

## Compatibility and scope disposition

The root Cargo/README minimum remains 1.97.1; nine member declarations inherit
it, and viewer-source/tools retain their omissions. The new chunk-array methods
are available before the retained minimum. The native all-feature check covers
the actual canonical lint surface; the WASM default-feature check covers its
established apps and worker. No new exhaustive feature or binding promise is
invented. `Cargo.lock` is identical to baseline, SHA-256
`8659266333ffacc69d40ab7f31336801acb800ff05cf1375c09a7bef6a3aeb75`, and the
viewer codec remains `6586e3d50f95429b242cb2e3535742b002784f2d`. E1's terminal
owner evidence is consumed without rerunning its components or changing its APIs.
Historical 1.97.1 measurements and provenance records remain unchanged.

The bounded pre-existing JPIP failure is repaired and qualified here. Protected
real-image acceptance, representative 43,008-wide system performance, every
browser/GPU and unrestricted input support remain governed by their existing
qualification plans; this compiler package creates no broader claim.
