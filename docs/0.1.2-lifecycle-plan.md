## Outcome

Close the remaining lifecycle and boundary gaps identified by the 0.1.1 review
without adding user-facing capability. Worker failure, zero-viewport rendering,
gesture completion and render-plan submission must have explicit terminal
semantics. Diagnostics and pane APIs must describe and enforce what the
application actually does.

## Exploration question and exit condition

Question: what is the smallest lifecycle protocol that keeps desired work,
worker availability, renderer maintenance and frame presentation consistent
when no image callback is available to make progress?

Representative probes:

- worker construction failure before the first demand and worker failure before
  a later demand;
- an obsolete decoded tile acknowledged after renderer admission, followed by a
  re-demand for the same key;
- pending renderer upload while every image pane is hidden behind a non-image
  tab;
- a wheel burst whose originating pane becomes hidden, and a linked burst that
  crosses panes;
- mismatched or reordered render requests and staged callback targets;
- a warmed idle interval after all zero-viewport maintenance has drained.

Evidence owners are focused runtime, renderer, UI bridge and application tests;
Rust-owned browser semantic actions and snapshots; structured diagnostics; and
the canonical native and browser smoke harnesses. Exploration exits when one
coherent candidate passes focused native and Wasm checks, every probe has a
deterministic assertion, and `cargo xtask verify` succeeds.

## Selected boundaries

- Runtime transport is explicit. Native instances never fall through to the
  browser external queue, event-channel disconnection is terminal after the
  final dispatch, invalid pyramid levels are rejected before admission, and a
  terminal worker state converts newly desired work directly to a failed
  resource state.
- Renderer frame maintenance is staged once per application frame independently
  of image callbacks. Image callbacks only prepare and paint image jobs.
- Render requests and staged targets correspond by pane identity; a mismatch is
  an ordinary checked error in every build profile.
- Wheel gestures are keyed by camera link scope and expired from one
  frame-global lifecycle pass, not from the presenter that happened to receive
  the originating input.
- Feature presenters emit explicit application-owned intents for authoritative
  tool, annotation-selection and display changes. Mutable presentation state is
  exposed only through feature-scoped interfaces.
- Metrics distinguish paint callbacks, returned command buffers and unavailable
  actual render-pass topology.

## Rejected paths

- Do not keep native-to-browser queue fall-through as a test convenience; tests
  must opt into an explicit external transport.
- Do not rely on a hidden synthetic image pane to drive uploads; maintenance is
  a renderer lifecycle concern rather than a visible-pane concern.
- Do not repair request/target mismatch with assertions or truncating `zip`;
  submission must validate before publishing any callback payload.
- Do not add widgets, analytical capabilities, a render graph or a second dock
  model during this pass.

## Delivery phases

1. Close worker-unavailable and obsolete-resource lifecycle semantics.
2. Make renderer maintenance independent of image visibility, validate the
   render plan and correct metrics.
3. Finalise wheel gestures frame-globally and split/narrow pane presentation.
4. Add semantic zero-viewport/failure evidence and update the report.
5. Run `cargo xtask verify`, independently review the exact head, repair any
   blocking finding and land through one pull request.
